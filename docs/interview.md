# 音视频面试题库

> 用法：先记录问题，不急着背答案。每完成一个实验，再补对应答案。

## Day 1

1. FFmpeg 和 ffprobe 分别解决什么问题？
- ffmpeg 是处理媒体，ffprobe 是分析媒体。

2. 为什么音视频学习需要同时掌握命令行工具和 C++ API？
- 命令行适合快速验证流程，C++ API 适合真正集成到项目中。

3. CMake 和 Ninja 在 C++ 工程里分别负责什么？
- cmake 负责生成工程构建配置，ninja 负责快速编译。

## Day 2

1. MP4、H.264、AAC 三者分别是什么？
- MP4 是封装格式，H.264 是视频编码格式，AAC 是音频编码格式。

2. `ffprobe` 输出里的 `FORMAT` 和 `STREAM` 有什么区别？
- FORMAT 描述整个媒体文件的信息，STREAM 描述具体的音视频流信息。

3. 为什么一个 mp4 文件可以同时有视频流和音频流？
- 因为 MP4 是容器格式，可以同时封装多种不同类型的媒体流。

4. 码率、帧率、分辨率分别描述什么？
- 码率描述数据量大小，帧率描述每秒画面数量，分辨率描述画面清晰度。

5. 采样率和声道数分别描述什么？
- 采样率描述音频每秒采样次数，声道数描述声音的通道数量。

## Day 3

1. 为什么 `.mp4` 不能直接等同于 “H.264 视频”？
- 因为 MP4 是容器，H.264 是视频编码格式。MP4 可以装 H.264，也可以装别的视频编码；它还可以同时装音频流和元数据。

2. `-c copy` 为什么能把 MP4 变成 FLV / TS？
- 因为这是重新封装：直接复制原有编码流，只替换外层容器。前提是目标容器支持这些流。

3. 重新封装之后，视频编码和音频编码是否发生了变化？
- 没有。今天三个文件里的视频仍然是 H.264，音频仍然是 AAC。

4. 如果容器变了但编码没变，这说明容器和编码格式之间是什么关系？
- 容器负责组织和承载媒体流，编码格式负责描述媒体数据如何压缩。它们是两层不同概念。

## Day 4

1. 对 `.h264` 裸流跑 `ffprobe` 为什么会看到 `Duration: N/A`？
- 因为时长信息存在容器（moov 盒子）里，裸流没有容器，ffprobe 无法获取精确时长，连 fps 都只能从 SPS 猜测，结果不可靠。

2. H.264 在 MP4 里和在 `.h264` 裸流文件里有什么格式区别？
- MP4 里用 AVCC 格式：每个 NALU 前是 4 字节长度前缀，SPS/PPS 存在容器 extradata 里。裸流文件用 Annex B 格式：每个 NALU 前是 `00 00 01` 或 `00 00 00 01` start code。FFmpeg 抽流时自动完成转换。

3. 从 MP4 抽出的 `.aac` 文件为什么时长不准确？
- AAC 写成独立文件时使用 ADTS 格式，每帧只有 7 字节帧头（含采样率、声道数、帧长度），没有全局索引，ffprobe 只能靠码率估算时长，所以不准（实测 30s 被估算成 31.43s）。

4. 容器相比裸流提供了哪些额外能力？
- 精确时长和时间戳索引（可 seek）、多路流同步、元数据存储、编码参数初始化（extradata）。moov 盒子是这些能力的载体，也是容器相比裸流多出来那部分开销（本次实验约 24KB）。

## Day 5

1. 为什么指定 `-b:v 200k` 反而让文件从 912KB 变大到 1.1MB？
- 原始文件用 CRF（质量优先）编码，编码器只用了 111kb/s 就达到了合适质量。`-b:v 200k` 强制编码器填入更多 bit，对于画面简单的内容这些 bit 没有带来画质提升，只是浪费了空间。

2. CRF 和固定码率（`-b:v`）的核心区别是什么？
- CRF 是质量优先：编码器自动决定用多少 bit 来维持目标质量，内容简单则 bit 少，内容复杂则 bit 多，结果是文件大小可变但质量稳定。固定码率是带宽优先：适合需要控制传输码率的场景（如直播推流），但对简单内容可能浪费 bit，对复杂内容可能画质不足。

3. GOP 是什么？大小对直播和点播分别意味着什么？
- GOP（Group of Pictures）是两个 I 帧之间的帧序列。GOP 越小，seek 越快、延迟越低，但 I 帧占比高，文件略大；GOP 越大，文件更小，但 seek 慢。直播/RTC 通常用 1-2 秒短 GOP 保证低延迟，点播可以用更长的 GOP（libx264 默认 250 帧，约 8 秒）。

4. 为什么 `-vf scale` 和 `-c:v copy` 不能同时使用？
- `-c:v copy` 直接复制已编码的视频数据，不经过解码和重编码。`-vf scale` 需要先解码成原始帧再缩放再重新编码，这两个操作互相矛盾，FFmpeg 会报错或忽略其中一个。
